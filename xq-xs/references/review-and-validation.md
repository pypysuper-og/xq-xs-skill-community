# 審查、除錯與驗證證據

## 除錯的最小輸入

先讀完整錯誤訊息及行號、腳本類型、相關宣告與呼叫。若是資料或執行結果問題，再確認 XQ 版本、商品、頻率、日期及洗價模式。只有會改變診斷的缺漏才詢問。

使用 `Print` 或選股輸出觀察條件時，同時記錄所屬 bar 日期、原始資料、中間變數與結果。不要只看最終買賣點；不要輸出帳戶識別或憑證。[Print](https://xshelp.xq.com.tw/XSHelp/?HelpName=Print&group=GENERALFUNC)

先還原失敗情境，再作最小修正。若只是查錯或審查，不擅自重寫策略。無法安全重現時，保留靜態依據與未確認的假設。

## 依問題選檢查

| 表現 | 優先看哪裡 |
|---|---|
| 編譯錯誤 | 宣告、函數參數、`else` 前分號、實際腳本類型、型別／名稱 |
| 有編譯但數值錯 | 初值、歷史引用、頻率對位、缺值、單位、遞迴計算 |
| 回測和即時不同 | GetQuote、當期未完成資料、發布時間、逐筆／bar 模式 |
| 警示次數不符 | 平台通知設定、訊號事件與狀態、去重範圍和重置 |
| 有訊號卻不符合委託預期 | 首個交易指令、快照時機、價格、Position／Filled 差異 |
| 部分成交後卡住 | 是否被全部成交條件擋住退出，取消與平倉是否混淆 |

審查先報編譯或會改變結果的問題，再報維護性建議。每個問題說明觸發情境、實際影響與最小修正；沒有證據時標成待確認，不冒充已重現缺陷。

## 分別記錄已執行的項目

| 驗證項目 | 可以支持的結論 | 仍不支持 |
|---|---|---|
| 靜態查核 | 來源、結構、型別與可見邏輯已檢視 | XQ 已接受或已執行 |
| XQ 編譯 | 指定版本、腳本類型可編譯 | 歷史／即時行為正確 |
| 指定資料／回測 | 該商品、頻率、期間與設定的歷史行為 | 未來獲利、實盤成交 |
| 模擬交易 | 已觀察的洗價、委託、成交情境 | 真實市場一定同樣執行 |
| 經授權的實盤觀察 | 該次實際操作與回報 | 所有商品與未來市場皆有效 |

這些是不同證據，並非完成一項即可推論全部較低層級都通過。報告實際執行的項目；只改一段宣告通常不需啟動完整交易生命週期測試。

交付 XS 程式而未在 XQ 使用時，直接寫「僅完成靜態查核；未在 XQ 編譯或執行」。Python 索引工具、Markdown 檢查與 ZIP 測試，都不是 XS compiler 或策略驗證器。

## 可重用的簡短回報

```text
腳本類型與情境：...
修改／判斷：...
關鍵官方來源：...
實際驗證：...
尚需在 XQ 核對：...
```

解釋單一函數時不必填滿表單；交易程式才補上對當前策略有意義的風控與未成交限制。
