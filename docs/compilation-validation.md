# XQ 桌面編譯驗證

日期：2026-11-08 至 2026-11-09（台灣時間）。環境：Windows、Python 3.13.5、XQ 全球贏家個人版 **3.20.04 261006**，已登入的互動桌面。測試經桌面操作工具執行，使用者接回控制權時停止桌面操作。

## 實際走過的流程

Agent 寫出 UTF-8 XS 檔，CLI 透過 XQ 的「開啟 XS 檔案」建立唯一名稱的腳本，選取對應類型，讀回編輯器完整文字比對，再送 F6。結果來自該唯一名稱的實際 XQ 編譯輸出與唯讀本機紀錄，沒有用靜態規則模擬編譯器。

最初另以最小指標驗證一支正確程式與一支缺少右括號的程式，分別得到 0 與 3 項編譯錯誤。後續四類案例使用同一個 CLI 入口。

| 類型／原創範例 | 正確例通過時間 | 故意寫錯的回讀證據 | 修正後通過時間 |
|---|---|---|---|
| indicator / ma-indicator.xs | 11-09 00:10:40 | XQ 診斷指出未知 `XqCliTypoProbe` | 11-09 00:33:26 |
| filter / ma-screen.xs | 11-09 00:12:30 | 輸出確認 2 項錯誤；可見表格顯示第 21 行、第 10 字元的未知識別字 | 11-09 00:33:51 |
| sensor / ma-alert.xs | 11-09 00:14:08 | 輸出確認 1 項錯誤，取得未知識別字的文字診斷 | 11-09 00:34:20 |
| autotrade / ma-autotrade-disabled.xs | 11-09 00:15:24 | 輸出確認 1 項錯誤，取得未知識別字的文字診斷 | 11-09 00:34:47 |

負例在各自原創範例後加上 `Value1 = XqCliTypoProbe;`。Agent 根據回讀的未知識別字診斷，將該處改成 `Value1 = Close;`，每類只作一次修正與重新編譯。四個修正版均回報 0 錯誤、0 警告。這是 Agent 讀結果後修正來源的流程，CLI 本身不會呼叫模型或自動重寫程式。

## 發現與處理的差異

- XQ 匯入 UTF-8 BOM 時，曾把開頭讀成 `?`。CLI 的來源比對攔下該次請求，**未觸發 F6**；提交檔改為 UTF-8 無 BOM 後，含中文註解的來源也通過完整比對與編譯。
- 選股負例的本機紀錄停在 `CompileStatus=7`、epoch 日期、空錯誤訊息；只讀資料庫會漏掉這種前端失敗。該次未重新編譯，而是從仍保留的輸出讀回終止狀態，並擷取結果表格。CLI 已加入同一份輸出讀取與表格擷取邏輯，另以確定性測試覆蓋 epoch 含毫秒的情況。
- 表格擷取在該桌面的 125% 縮放下已實際檢視，腳本名稱、錯誤描述與行列位置可讀。CLI 不將圖片自動解析為文字；JSON 的行列位置仍為 `null`。可見表格只有一列，不代表編譯器輸出的全部錯誤數。
- 指標、警示與交易負例保存的診斷包含重複訊息及額外的物件參考例外。CLI 保留原始文字、另外提供去重後的訊息，避免把訊息筆數冒充編譯錯誤數。

原始請求、輸入及提交雜湊、唯一名稱、結果 JSON 和圖片保留在操作者指定的本機證據目錄；未放入公開套件。最後更新的四個範例註解只調整驗證狀態，執行程式沒有改動。

## 重現入口

從專案根目錄、已授權且空閒的 XQ 桌面執行：

```text
python xq-xs/scripts/xq_compile.py doctor --json
python xq-xs/scripts/xq_compile.py compile xq-xs/assets/examples/ma-screen.xs --type filter --work-dir ./compile-evidence --timeout 90 --json
```

完整前提、結果欄位與停止條件見 [桌面編譯指南](../xq-xs/references/desktop-compile.md)。機器環境、資料及 XQ 介面漂移都可能影響重現；目前未建立官方 API 相容性保證。

## 可以支持與尚未驗證的事項

已支持四種指定案例的「匯入、來源／類型核對、編譯、讀結果、Agent 修正後再編譯」。工具可離開 Agent 直接執行，但**必須有 XQ 桌面程式配合**。

未測試其他 XQ 版本／企業版、不同介面語言、無頭 CI、自訂函數編譯、所有錯誤表格列的完整擷取、鎖定或斷線桌面、不同權限層級，以及長時間批次使用。沒有執行策略、回測、啟用雷達、模擬或真實送單。

目前維持一份可安裝 Skill，並隨附獨立可呼叫的 Python CLI，讓寫作參考與操作工具共用來源和版本。不需要先引入 CLI-Anything 框架或另開重複專案。若未來出現多個獨立消費者、需要獨立發布或支援多種 XQ 介面，再評估拆成正式的 companion package。
